# 안티 커닝

시험장 주변의 **BLE / 블루투스 / Wi-Fi** 신호를 탐색해 새로 나타난 신호를 찾고,
의심스러운 신호를 목록 맨 위에 표시한 뒤, 선택한 신호의 **세기·접근 여부·방향**을 추적하는 안드로이드 앱입니다.

## APK 만드는 방법

### A. GitHub Actions로 자동 빌드 (설치 없이 가장 쉬움)
1. 이 zip의 압축을 풀고, **폴더 안의 내용물 전체**(`app`, `gradle`, `.github`, `build.gradle.kts` …)를 GitHub 저장소에 올립니다.
   - 빈 저장소 화면에서는 **"uploading an existing file"** 링크를 누르면 업로드 화면이 열립니다.
   - 이미 파일이 있는 저장소라면 **Add file > Upload files** 입니다. (Add file 버튼은 저장소 위쪽 `Code` 탭에 있습니다.)
   - `.github` 폴더가 빠졌다면 `Add file > Create new file`에서 파일 이름에 `.github/workflows/build.yml`을 입력하고 같은 내용을 붙여넣으세요.
2. **Actions** 탭 → `Build APK` 실행이 끝나면(3~5분) **Artifacts**의 `signal-detector-apk`를 내려받습니다.
3. 압축을 풀면 `app-debug.apk`가 나옵니다.

### B. Android Studio
`File > Open`으로 이 폴더를 열고 `Build > Build APK(s)` → `app/build/outputs/apk/debug/app-debug.apk`

### C. 명령줄
JDK 17 + Android SDK가 있는 PC에서 `./gradlew assembleDebug`

## 폰에 설치·권한
APK를 폰으로 옮겨 실행합니다("출처를 알 수 없는 앱 설치" 허용 필요).
처음 실행하면 **근처 기기 / 위치 권한**을 묻습니다. 허용하고 **위치(GPS), 블루투스, Wi-Fi를 켜 두세요**
(안드로이드는 위치가 꺼져 있으면 주변 신호 목록을 주지 않습니다).

## 사용법
1. **탐색 시작** → 처음 15초는 기준 수집 구간입니다. 이때 보인 신호는 "기존 신호"입니다.
2. 이후 처음 나타난 신호에는 **NEW**가 붙습니다.
3. **의심 신호는 목록 맨 위**에 올라오고, 왼쪽 색 막대·배경색·`⚠ 주의 / 의심 / 강한 의심` 배지와
   **분류**(예: "무선 이어폰 (AirPods Pro 추정)")·**의심 이유**가 함께 표시됩니다.
4. 신호를 누르면 추적 화면이 열립니다: 세기 그래프, ▲가까워짐/▼멀어짐, 대략적 거리,
   그리고 제자리에서 천천히 한 바퀴 돌면 신호가 오는 **방향**을 화살표로 알려줍니다.

### 필터·설정 (목록 위 "필터·설정" 버튼)
| 항목 | 설명 |
|---|---|
| 새 신호만 / 의심 신호만 | 항상 보이는 스위치 |
| 이름 없는 BLE 기기만 | 이름을 방송하지 않는 BLE 기기만 표시 |
| Wi-Fi는 숨김·핫스팟 의심만 | 숨겨진 SSID, 핫스팟 이름 패턴, Wi-Fi Direct만 남김 (블루투스 항목은 그대로) |
| Wi-Fi 대역 | 전체 → 2.4GHz만 → 5GHz 이상만 (누를 때마다 순환) |
| 감시 Wi-Fi 채널 설정 | 입력한 채널의 Wi-Fi 신호에 "감시 채널" 표시와 점수를 부여. 기본값은 2.4GHz 12·13·14 (일반 공유기가 거의 쓰지 않는 채널). 저장되어 다음 실행에도 유지됩니다. |

## 분류와 의심 점수는 어떻게 정해지나
광고 패킷 안의 힌트로 **추정**합니다. 점수 합계가 1이면 `주의`, 2~3이면 `의심`, 4 이상이면 `강한 의심`입니다.

**BLE / 클래식 블루투스**
- 무선 이어폰(+3): Apple 근접 페어링 패킷(AirPods·Beats, 모델명 일부 식별), Google Fast Pair, Appearance 값, 이름(Buds·Headset 등)
- 스마트워치·웨어러블(+2): Apple Watch(손목 착용 활동 코드), 이름(Watch·Band 등), 심박 서비스, Appearance
- 스마트폰·태블릿(+1): 이름·Appearance·Apple 연속성 패킷. **Apple 기기는 패킷만으로 폰/태블릿/맥을 구분할 수 없어** "스마트폰·태블릿·맥"으로 표시합니다.
- 소형 통신기기 칩 제조사(+2): Espressif(ESP32), Nordic, Telink, Dialog 등의 제조사 ID, 샤오미 계열 서비스
- **이름·제조사·서비스 정보가 전혀 없는 BLE 기기(+2): '이름 없는 미확인 소형 기기'**
- 소형 추적 태그(+1): AirTag, Tile, SmartTag 등
- iPhone 인스턴트 핫스팟 관련 패킷(+2)
- 위 항목이 하나라도 있고 신호가 -50dBm보다 강하면(매우 가까움) +1

**Wi-Fi**
- 숨겨진 SSID +2 · 스마트폰 핫스팟 이름 패턴(iPhone, Galaxy, AndroidAP 등) +3 · Wi-Fi Direct(`DIRECT-`) +2
- 감시 채널 +2
- 임의(로컬) MAC 주소는 위 항목이 있을 때만 +1 (핫스팟·가상 AP에서 흔함)

## 알아둘 점 (한계)
- **오탐이 많습니다.** 에어팟·스마트워치·폰은 시험장 밖에서도 흔하고, 시험장 주변 다른 사람의 기기와 구분되지 않습니다.
  이름 없는 BLE 기기 대부분은 평범한 주변 기기입니다. 점수는 "확인해 볼 후보"를 추리는 용도일 뿐 증거가 아닙니다.
  특정 학생을 지목하는 근거로 쓰지 말고, 반드시 직접 확인하세요.
- 아이폰 등은 블루투스 주소를 주기적으로 바꿔서 같은 기기가 "새 신호"로 다시 잡힐 수 있습니다.
- 이 앱은 신호의 **존재와 세기**만 봅니다. 통신 내용은 알 수 없고, 신호가 부정행위에 쓰이는지도 알 수 없습니다.
- 핫스팟 이름 패턴은 기본 이름(iPhone, Galaxy…) 기준이라, 이름을 바꾼 핫스팟은 잡히지 않고 숨김 SSID로만 잡힐 수 있습니다.
- **BLE가 가장 정확하게 추적됩니다.** 클래식 블루투스와 Wi-Fi는 측정 간격이 길어 추세·방향이 느리게 반영됩니다.
  개발자 옵션의 "Wi-Fi 스캔 제한"을 끄면 더 자주 갱신됩니다.
- 거리와 방향은 전파 세기로 추정한 값이라 벽, 사람 몸, 반사 때문에 오차가 큽니다.

## 구조
```
app/src/main/java/com/example/signaldetector/
  MainActivity.kt    화면(목록/추적/필터), 권한, 센서
  SignalScanner.kt   BLE·클래식 블루투스·Wi-Fi 스캔
  Analyzer.kt        패킷 해석, 기기 분류, 의심 점수 (순수 코틀린)
  SignalTracker.kt   세기 평활, 추세, 거리, 방향 추정
  Models.kt          신호 모델, 새 신호 판정(기준 구간)
  Views.kt           나침반 뷰, 그래프 뷰
```
